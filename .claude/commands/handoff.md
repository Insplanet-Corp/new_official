# CLAUDE.md 인수인계 갱신

프로젝트 루트의 `CLAUDE.md`를 지금 상태에 맞게 갱신한다.

## 먼저 확인할 것

```
!`git log --oneline -15`
!`git status --short`
!`git branch --show-current`
!`git log --oneline main..HEAD 2>/dev/null | head -20`
```

사용자가 남긴 메모: $ARGUMENTS

## 하는 일

1. **현재 `CLAUDE.md`를 읽는다.** 통째로 새로 쓰지 말고, 바뀐 부분만 고친다.
   기존에 정리해 둔 제약·결정 사항은 여전히 유효한지 확인하고 유지한다.

2. **마지막 갱신 이후 무엇이 바뀌었는지 파악한다.** 위 git 출력과 이번 세션에서
   실제로 한 작업을 대조한다. 커밋되지 않은 변경이 있으면 그것도 반영한다.

3. **아래 기준으로 갱신한다.**

   담을 것 — *코드를 읽어서는 알 수 없는 것*:
   - 왜 그렇게 했는지 (특히 흔한 방식을 택하지 *않은* 이유)
   - 시도했다가 안 됐던 것과 그 이유 → 다음에 같은 삽질을 막는다
   - 측정한 수치 (성능, 크기 등) — 근거 없는 주장 대신 숫자로
   - 사용자와 합의한 결정, 미해결 질문
   - 밟았던 지뢰 / 조용히 깨지는 함정
   - 검증하지 *못한* 것 (중요 — 다음 세션이 확인해야 할 것)

   담지 말 것:
   - 코드 구조 설명 (README.md 담당)
   - 파일 목록, 함수 시그니처 — 코드에 이미 있다
   - 이번 대화에서만 의미 있는 진행 상황 서술

4. **정확성이 최우선이다.** 확인하지 않은 것을 확인한 것처럼 쓰지 말 것.
   빌드가 깨진 상태면 깨졌다고 쓰고, 육안 검증을 못 했으면 못 했다고 쓴다.

5. **분량을 관리한다.** 이 문서는 매 세션 컨텍스트에 로드된다. 오래돼서 더는
   의미 없는 항목(이미 해결된 이슈, 지나간 TODO)은 지운다. 계속 늘리지 말 것.

6. 갱신이 끝나면 **`CLAUDE.md`만 별도 커밋한다.** 다른 변경과 섞지 않는다.
   작업 자체를 아직 커밋하지 않았다면 그것부터 커밋하고 나서 문서를 커밋한다.

마지막으로 무엇을 추가·수정·삭제했는지 한눈에 보이게 요약해 알려준다.
